# D2 学习笔记

## 1. 阻塞赋值与非阻塞赋值

- 组合 `always @(*)` 通常使用阻塞赋值 `=`：右侧计算后立即更新左侧，后续语句能读到新值。
- 时钟 `always @(posedge clk)` 通常使用非阻塞赋值 `<=`：当前边沿先计算所有右侧，随后在 NBA 阶段更新左侧。
- `end` 不是非阻塞赋值的“提交命令”；更新时机由仿真调度区域决定。
- 时钟保持为 `1` 不等于上升沿；`posedge clk` 只指 `clk` 从 `0` 变到 `1` 的瞬间。

## 2. Race condition

当多个并发过程在同一仿真时刻执行，而结果会随执行先后顺序改变时，就存在 race condition。时序块使用 `<=`，并避免多个 `always` 块共同写同一个变量，可以规避常见竞态。

## 3. 组合过程与时序过程

- `assign` 和完整赋值的 `always @(*)` 都能描述组合逻辑。
- `always @(*)` 的 `*` 自动包含块内读取的相关信号；手写敏感列表若漏信号，可能造成 RTL 仿真与综合硬件不一致。
- `output reg` 只是传统 Verilog 对过程赋值左侧的语法要求，不代表一定综合出寄存器。
- `always @(posedge clk)` 会推断触发器；寄存器值只在上升沿更新，两个边沿之间保持。

## 4. Latch 与完整赋值

Latch 是电平敏感的存储元件：使能有效时输出跟随输入，使能无效时保持旧值。组合块中若某条控制路径没有给输出赋值，代码就要求输出保留旧值，综合器因而可能推断 latch。

避免意外 latch 的两种常用写法：

1. 为 `if/else`、`case/default` 补全所有输出的所有路径；
2. 在组合块开头为所有输出设置默认值，随后按条件覆盖。

“保留本轮已经设置的默认值”是组合逻辑；“本轮没有赋值而保留上一次值”需要存储元件。

## 5. case 与 casez

- 单个 case item 只有一条语句时，可以省略 `begin/end`；多条语句必须使用 `begin/end`。
- 普通 `case` 精确匹配每一位；`casez` 可用 `z` 或 `?` 表示不关心位。
- 优先编码器中，当前目标位写 `1`，更低编号位写 `0`，更高编号位写不关心，可得到互不重叠的模式。
- 防御性 `default` 可处理未匹配以及仿真中的 `x/z` 情况。

## 6. D1 代表题复做：32 位加减法器

核心关系：

```text
a - b = a + (~b) + 1
```

用 `b ^ {32{sub}}` 在加法和按位取反之间切换，并把 `sub` 接到低 16 位加法器的 `cin`。低 16 位的 `cout` 必须通过 `carry16` 接到高 16 位的 `cin`，形成完整的 32 位进位链。

本次复做中自行发现并修正：

- 首次遗漏低位 `cout` 到高位 `cin` 的 `carry16` 连接；
- `b_modified` 首次漏写 `[31:0]` 位宽。

修正后 HDLBits `Module_addsub` 提交通过。

## 7. D1 代表题复做：三级 8 位移位寄存器与多路选择器

HDLBits `Module_shift8` 使用三个 `my_dff8` 串联：

```text
d -> q1 -> q2 -> q3
```

- `q1`、`q2`、`q3` 是父模块中连接子模块输出与下一级输入的信号，由模块实例的输出端口驱动，因此声明为 `wire [7:0]`。
- `sel` 选择原始输入 `d`，或延迟 1、2、3 拍后的 `q1`、`q2`、`q3`。
- 本次使用 `always @(*) + case` 描述组合多路选择器；四种 `sel` 取值全部覆盖，不需要保存旧值。
- 传统、可移植的 Verilog 写法中，若最终输出 `q` 在 `always` 块内被过程赋值，应将其声明为 `output reg [7:0] q`，或使用内部 `reg` 后再以 `assign` 连接到输出。此次保留 HDLBits 自带的 `output [7:0] q` 仍被其判题环境接受并通过。

本次复做中自行发现并修正：

- 开始时短暂停顿，随后确认三级实例之间需要先声明 8 位连接线；
- 第一次提交时漏写各个 `case` item 后的冒号 `:`；
- 修正语法后提交显示 `Status: Success!`；
- 进一步确认：信号是否叫作 `q1/q2/q3`、是否来自触发器，并不能单独决定使用 `reg` 还是 `wire`；应看它在当前模块中由模块端口、连续赋值还是过程块驱动。

## 8. D1 代表题复做：复制、拼接与两两比较

HDLBits `Vector5` 要把 `a`、`b`、`c`、`d`、`e` 组成全部 25 组有序比较。本次独立写出：

```verilog
assign out = ~{{5{a}}, {5{b}}, {5{c}}, {5{d}}, {5{e}}}
             ^ {5{a, b, c, d, e}};
```

- 左侧向量排列为 `aaaaa_bbbbb_ccccc_ddddd_eeeee`；
- 右侧向量排列为 `abcde_abcde_abcde_abcde_abcde`；
- 两个向量逐位异或，并对其中一侧逐位取反，等价于逐位 XNOR；
- 因此 `out[24]` 比较 `a` 与 `a`，`out[0]` 比较 `e` 与 `e`，整体顺序正确；
- 两个操作数均为 25 位，提交显示 `Status: Success!`。

## 9. 阻塞、NBA 与竞态递进检查

### 同一时钟块中的赋值传播

- 时钟块中连续使用阻塞赋值 `=` 时，左侧在 Active 阶段立即更新，后续语句会读到新值；三级寄存器代码可能在 RTL 仿真中出现单拍穿透。
- 同一块混用 `=` 和 `<=` 时，某条语句可能读到旧值，也可能读到前一条阻塞赋值刚写入的新值，行为难以检查，因此应避免混用。
- 非阻塞赋值 `<=` 在 Active 阶段计算右侧，并在 NBA 阶段更新左侧，使多级寄存器按拍传递。

### 并发过程之间的竞态

- 两个 `always @(posedge clk)` 在同一时刻被唤醒，其 Active 阶段执行先后没有保证；若一个块以 `=` 更新信号而另一个块同时读取它，后者可能读到旧值或新值。
- 即使都使用 `<=`，多个过程共同写同一个变量仍会发生冲突；一个寄存器应只有一个明确的时序赋值过程，由该过程内部的 `if/else` 或 `case` 明确选择与优先级。
- 把写同一寄存器的正常更新、复位和使能拆到多个时序块，是常见的多重驱动错误。

### Testbench 与 DUT 的竞态

若 Testbench 恰好在 DUT 的采样上升沿用阻塞赋值改变输入，Testbench 驱动与 DUT 采样都发生在 Active 阶段，DUT 可能读到变化前或变化后的值。简单练习中可在下降沿驱动输入，使输入在下一个上升沿前稳定半个周期，从而避免同一事件区域的竞争。
